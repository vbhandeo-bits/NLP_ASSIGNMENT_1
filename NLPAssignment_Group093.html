Part 2: Model Architecture & Parameter Estimation¶

This section focuses on building a fundamental Bigram Hidden Markov Model from scratch. We will estimate the Transition Probability Matrix (A) and Emission Probability Matrix (B) using Maximum Likelihood Estimation (MLE) from the training data.

Estimate the Transition Probability Matrix (A)¶

The Transition Probability Matrix $A_{ij}$ represents the probability of transitioning from state (POS tag) $i$ to state (POS tag) $j$. We estimate this using Maximum Likelihood Estimation (MLE) based on the observed tag sequences in the training data:

$A_{ij} = P(tag_j | tag_i) = \frac{Count(tag_i, tag_j)}{Count(tag_i)}$

We include the start (<s>) and end (</s>) tokens in our tag set to handle sentence boundaries.

Estimate the Emission Probability Matrix (B)¶

The Emission Probability Matrix $B_{jk}$ represents the probability of observing a word $k$ given a state (POS tag) $j$. Similar to the transition matrix, we estimate this using Maximum Likelihood Estimation (MLE) from the training data:

$B_{jk} = P(word_k | tag_j) = \frac{Count(tag_j, word_k)}{Count(tag_j)}$

We will also handle the _UNKNOWN_ token here, assigning a small probability to it for all tags to avoid zero probabilities for unseen words in the test set.

# Initialize counts for emissions
tag_word_counts = defaultdict(lambda: defaultdict(int))
tag_frequencies_for_emission = defaultdict(int) # New dictionary to correctly count tag occurrences for emission

# Populate tag_word_counts and tag_frequencies_for_emission
for sent in train_sentences_padded:
    for word, tag in sent:
        # Only process actual content words/tags for emission probabilities.
        # Special START_TOKEN and END_TOKEN do not emit words, so they are excluded.
        if tag not in [START_TOKEN, END_TOKEN]:
            word_lower = word.lower()
            tag_word_counts[tag][word_lower] += 1
            tag_frequencies_for_emission[tag] += 1 # Count every occurrence of the tag

# Calculate Emission Probability Matrix (B) using log-probabilities
# B[tag][word] = log(P(word | tag))
# Initialize with -np.inf for unseen emissions
emission_probabilities = defaultdict(lambda: defaultdict(lambda: -np.inf))

ALPHA = 1e-6 # A small constant for smoothing unknown words
LOG_ALPHA = np.log(ALPHA) # Log of the smoothing constant

for tag, words_in_tag in tag_word_counts.items():
    total_tag_count = tag_frequencies_for_emission[tag] # Use the new, correct tag count

    # This check ensures we don't divide by zero if, somehow, a tag with word counts has zero total frequency
    if total_tag_count == 0:
        # If a tag has no words, its emission probabilities should all be very small (LOG_ALPHA)
        # This handles cases where a tag might only appear with START/END tokens or is very rare
        for word in vocabulary: # Assign LOG_ALPHA to all words for this tag if total_tag_count is zero
            emission_probabilities[tag][word] = LOG_ALPHA
        emission_probabilities[tag][UNKNOWN_TOKEN] = LOG_ALPHA

    # Calculate probabilities for known words
    for word, count in words_in_tag.items():
        emission_probabilities[tag][word] = np.log(count / total_tag_count)

    # Handle UNKNOWN_TOKEN: assign a small, non-zero probability to it for every tag.
    # This loop iterates over keys from tag_word_counts, which already excludes START/END_TOKEN.
    emission_probabilities[tag][UNKNOWN_TOKEN] = LOG_ALPHA # Assign log(ALPHA) to the OOV token

Implement the Viterbi Algorithm¶

The Viterbi algorithm is a dynamic programming algorithm for finding the most likely sequence of hidden states (Viterbi path) that results in a sequence of observed events, especially in the context of Hidden Markov Models (HMMs).

Here's a high-level overview of the steps:

  1. Initialization: For the first word, calculate the probability of each POS tag being the starting tag and emitting the first word.
  2. Recursion: For each subsequent word, and for each possible current POS tag, calculate the maximum probability of reaching this tag, given all previous paths and the probability of emitting the current word.
  3. Termination: Find the most probable sequence ending with the end-of-sentence token.
  4. Path Backtracking: Reconstruct the sequence of POS tags by backtracking through the stored paths.

    Implements the Viterbi algorithm to find the most likely sequence of POS tags for a given sequence of words.
    This version uses log-probabilities to prevent numerical underflow.

    Args:
        words (list): A list of words (observations) in a sentence.

        ALPHA (float): Small constant used for smoothing (will be converted to LOG_ALPHA).

    Returns:
        tuple: A tuple containing the most likely sequence of POS tags and its probability.
    """

    LOG_ALPHA = np.log(ALPHA)

    # Number of words in the sentence and number of possible POS tags
    num_words = len(words)
    # Filter out START_TOKEN and END_TOKEN from all_pos_tags for Viterbi processing,
    # as these are boundary tags and not actual POS tags for words.
    viterbi_tags = [tag for tag in all_pos_tags if tag not in [START_TOKEN, END_TOKEN]]
    num_tags = len(viterbi_tags)

    # Create a mapping from tag string to its index for efficient NumPy array access
    tag_to_idx = {tag: i for i, tag in enumerate(viterbi_tags)}
    idx_to_tag = {i: tag for i, tag in enumerate(viterbi_tags)}

    # Initialize Viterbi table and backpointer table
    # viterbi_table[t][tag_idx] stores the maximum log-probability of a tag sequence ending with tag_idx at time t
    # backpointer[t][tag_idx] stores the index of the previous tag that led to the maximum log-probability
    viterbi_table = np.full((num_words, num_tags), -np.inf) # Initialize with negative infinity for log-probs
    backpointer = np.zeros((num_words, num_tags), dtype=int)

    # --- Initialization Step (t = 0) ---
    # For the first word, calculate the log-probability of each POS tag being the first tag
    # log(P(tag_i | START_TOKEN) * P(word_0 | tag_i)) = log(P(tag_i | START_TOKEN)) + log(P(word_0 | tag_i))
    first_word = words[0].lower()

    for i, current_tag in enumerate(viterbi_tags):
        # Log-probability of transitioning from START_TOKEN to current_tag
        log_prob_start_to_tag = transition_probabilities[START_TOKEN].get(current_tag, LOG_ALPHA)

        # Emission log-probability of the first word given the current_tag
        # If the word is OOV and becomes UNKNOWN_TOKEN, its log-probability is LOG_ALPHA (set during emission matrix calc).
        # If the word is a known word not seen with this tag, use LOG_ALPHA for smoothing.
        log_prob_word_given_tag = emission_probabilities[current_tag].get(first_word, emission_probabilities[current_tag].get(UNKNOWN_TOKEN, LOG_ALPHA))

        viterbi_table[0, i] = log_prob_start_to_tag + log_prob_word_given_tag
        # No backpointer for t=0

    # --- Recursion Step (t = 1 to num_words - 1) ---
    # For each subsequent word, calculate the maximum log-probability for each possible current tag
    for t in range(1, num_words):
        current_word = words[t].lower()

        for j, current_tag in enumerate(viterbi_tags):
            max_log_prob = -np.inf # Initialize with negative infinity
            best_prev_tag_idx = 0

            # Emission log-probability of the current word given the current_tag
            log_prob_word_given_tag = emission_probabilities[current_tag].get(current_word, emission_probabilities[current_tag].get(UNKNOWN_TOKEN, LOG_ALPHA))

            for i, prev_tag in enumerate(viterbi_tags):
                # Log-probability of path to previous tag + log-transition from prev_tag to current_tag + log-emission of current_word
                log_prob = viterbi_table[t-1, i] + transition_probabilities[prev_tag].get(current_tag, LOG_ALPHA) + log_prob_word_given_tag

                if log_prob > max_log_prob:
                    max_log_prob = log_prob
                    best_prev_tag_idx = i

            viterbi_table[t, j] = max_log_prob
            backpointer[t, j] = best_prev_tag_idx

    # --- Termination Step ---
    # Find the maximum log-probability of a path ending with a transition to END_TOKEN
    max_final_log_prob = -np.inf # Initialize with negative infinity
    last_tag_of_best_path_idx = 0

    for i, last_possible_tag in enumerate(viterbi_tags):
        # log(P(path_to_last_tag) * P(END_TOKEN | last_tag)) = log(P(path_to_last_tag)) + log(P(END_TOKEN | last_tag))
        log_prob = viterbi_table[num_words-1, i] + transition_probabilities[last_possible_tag].get(END_TOKEN, LOG_ALPHA)
        if log_prob > max_final_log_prob:
            max_final_log_prob = log_prob
            last_tag_of_best_path_idx = i

    # --- Path Backtracking ---
    # Reconstruct the best tag sequence by backtracking from the last tag
    best_path_tags = [idx_to_tag[last_tag_of_best_path_idx]]
    for t in range(num_words - 1, 0, -1):
        last_tag_of_best_path_idx = backpointer[t, last_tag_of_best_path_idx]
        best_path_tags.insert(0, idx_to_tag[last_tag_of_best_path_idx]) # Insert at the beginning

    return best_path_tags, np.exp(max_final_log_prob) # Return probability in linear scale

Further Discussion and Analysis (Recommendations for Excellence)¶

HMM Limitations¶

While our custom HMM implementation provides a solid foundation for understanding POS tagging, it inherently comes with several limitations, especially when compared to more advanced models like the PerceptronTagger or neural network-based approaches:

  1. Strict Independence Assumptions: HMMs assume that the current state (tag) only depends on the previous state (bigram assumption) and that the observed word only depends on its current tag. This overlooks longer-range dependencies, grammatical structures, and contextual information spanning multiple words, which are crucial for accurate tagging.
  2. Data Sparsity: With finite training data, many tag-word and tag-tag combinations might not appear. Even with smoothing (like our ALPHA constant), this leads to inaccurate probability estimates for unseen events, impacting performance on test data, especially for OOV words or rare linguistic phenomena.
  3. Generative Model: HMMs are generative models, meaning they try to model the joint probability of observations and hidden states, $P(O, S)$. For discriminative tasks like POS tagging (predicting $P(S|O)$), discriminative models often perform better because they directly model the conditional probability, avoiding the need to model the observation sequence itself.
  4. Inability to Incorporate Rich Features: A basic HMM cannot easily integrate complex features like word suffixes, prefixes, capitalization, or features from surrounding words (beyond the immediate previous tag). These features are vital for distinguishing between tags for ambiguous words, a capability that perceptrons and neural networks excel at.
  5. Viterbi Path Uniqueness: In cases of extremely low probabilities or multiple paths having similar (very small) probabilities, the Viterbi algorithm might pick an arbitrary path, which could lead to sub-optimal results if the true path's probability was marginally lower due to numerical precision or data sparsity.

These limitations explain why a simple HMM, despite being a powerful conceptual model, often underperforms against state-of-the-art methods that leverage richer features and more flexible architectures.

Time Complexity Analysis of the Viterbi Algorithm¶

The time complexity of the Viterbi algorithm can be analyzed based on its three main steps:

  1. Initialization: For the first word, we iterate through all possible tags. If there are $|S|$ possible states (POS tags), this step takes $O(|S|)$ operations.

  2. Recursion (Main Loop): This is the most computationally intensive part. We iterate through each word in the sentence (length $T$). For each word, we iterate through every possible current tag ($|S|$ tags). For each current tag, we then consider every possible previous tag ($|S|$ tags) to find the maximum probability path. Thus, this step involves $T \times |S| \times |S|$ operations.

  3. Termination and Backtracking: The termination step involves iterating through the last column of the Viterbi table, taking $O(|S|)$ operations. Backtracking involves iterating backwards through the sentence, performing $O(T)$ operations.

Combining these, the dominant factor is the recursion step. Therefore, the overall time complexity of the Viterbi algorithm is approximately $O(T \cdot |S|^2)$, where:

  • $T$ is the length of the observed sequence (number of words in the sentence).
  • $|S|$ is the number of hidden states (number of unique POS tags).

This quadratic dependence on the number of states $|S|$ means that the algorithm can become slow for models with a very large tag set. However, for typical POS tagging tasks with a relatively small number of universal tags (like 12 in our case), it is quite efficient.

Importance of Log-Probabilities in Viterbi¶

Our current Viterbi implementation uses raw probabilities, multiplying them at each step. While conceptually correct, this approach can lead to a significant practical issue: numerical underflow.

  • The Problem: Probabilities are values between 0 and 1. When you multiply many small probabilities together, the resulting product can become extremely small, quickly falling below the smallest representable floating-point number (machine epsilon). When this happens, the value gets truncated to 0, causing incorrect calculations and potentially leading to a Viterbi path with zero probability even if a valid path exists.

  • The Solution: Instead of multiplying probabilities, it is common practice to work with log-probabilities. The key properties that make this effective are:

    • log(a * b) = log(a) + log(b)
    • log(max(a, b)) = max(log(a), log(b)) (approximately, for numerical stability, though more precisely, it involves log(exp(log_a) + exp(log_b))).

    By converting all probabilities to their logarithmic form, multiplications become additions, and finding the maximum product becomes finding the maximum sum. Additions of negative log-probabilities (since log(p) for p<1 is negative) do not lead to underflow as quickly, as the values move towards larger negative numbers rather than smaller positive numbers.

  • Impact: Implementing Viterbi with log-probabilities significantly improves numerical stability, especially for longer sentences, preventing underflow issues and ensuring that the most likely path is correctly identified. While not strictly necessary for short sentences, it is a crucial consideration for robust production-level HMM implementations.

Interpretation of Metrics:¶

  • Precision: Out of all the times the model predicted a certain tag, how many were actually correct? A high precision means a low false positive rate.
  • Recall: Out of all the times a certain tag actually occurred, how many did the model correctly identify? A high recall means a low false negative rate.
  • F1-Score: This is the harmonic mean of Precision and Recall, providing a single metric that balances both. It's especially useful when dealing with imbalanced classes.

Averaging Methods:

  • Macro Average: Calculates the metric independently for each class and then takes the average. It treats all classes equally, regardless of their support (number of true instances).
  • Weighted Average: Calculates the metric for each class and averages them, weighted by the number of true instances for each class. This accounts for class imbalance.

These metrics provide a more detailed understanding of your model's performance beyond simple overall accuracy, indicating how well it performs on individual POS tags and how it handles false positives versus false negatives.

def convert_ptb_to_universal(ptb_tag):
    if ptb_tag.startswith('N'):
        return 'NOUN'
    elif ptb_tag.startswith('V'):
        return 'VERB'
    elif ptb_tag.startswith('J'):
        return 'ADJ'
    elif ptb_tag.startswith('R'):
        return 'ADV'
    elif ptb_tag.startswith('P'): # PRON, PRP$
        return 'PRON'
    elif ptb_tag.startswith('D'): # DT, PDT
        return 'DET'
    elif ptb_tag.startswith('I'): # IN
        return 'ADP'
    elif ptb_tag.startswith('C'): # CC
        return 'CONJ'
    elif ptb_tag.startswith('W'): # WDT, WP, WP$
        return 'DET' # Or PRON depending on context, using DET for simplicity for now
    elif ptb_tag.startswith('M'): # CD for numbers
        return 'NUM'
    elif ptb_tag in ['.', ',', ':', '``', "''", '-LRB-', '-RRB-']:
        return '.'
    elif ptb_tag.startswith('E'): # EX
        return 'PRT' # or ADV
    elif ptb_tag.startswith('T'): # TO
        return 'PRT'
    elif ptb_tag.startswith('F'): # FW
        return 'X'
    elif ptb_tag.startswith('L'): # LS
        return 'X' # List item marker
    elif ptb_tag.startswith('H'): # RP
        return 'PRT'
    else:
        return ptb_tag # Return original if no direct mapping, or map to 'X' (other)
